# M10 — trip export — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `trip export --format=ics|md|geojson` writes the plan out, and none of the three formats claims to know something the plan does not.

**Architecture:** One shared read-only view (`buildExportView`) over stored placements, reused by all three renderers and shape-identical to what `trip day` reads. Three pure renderer modules. One command.

**Tech Stack:** TypeScript strict, Bun, `bun:test`. No new dependencies — iCalendar and GeoJSON are both emitted directly.

## Global Constraints

- **Spec:** `docs/superpowers/specs/2026-07-27-trip-m10-design.md`. D1–D6 binding.
- **No schema migration.** M10 stays at v12.
- **Export reads STORED placements and never re-plans** (D1).
- **One shared build, three renderers** (D2). A divergence here is M8's `trip day` defect in the command whose job is faithful reproduction.
- Unknown is `null`; free is `0`. Never conflated, in any format.
- GeoJSON coordinates are **longitude, latitude** (RFC 7946).
- iCalendar folds at **75 octets**, not characters (RFC 5545).
- Always `bun`. Always `@/`. No backticks in commit messages.
- Commit after every task. **Do not push.**

### Task 1: The shared export view

**Files:**
- Create: `src/export/view.ts`
- Modify: `src/commands/plan.ts` (export the pieces the view needs)
- Test: `test/export-view.test.ts`

**Interfaces:**
- Produces: `ExportStop`, `ExportHop`, `ExportDay`, `ExportView`, `buildExportView(db)`.

```ts
export interface ExportHop {
  minutes: number;
  measured: boolean;
  mode: Mode;
}

export interface ExportStop {
  segmentId: number;
  name: string;
  /** OSM's own name where it DIFFERS from `name`. M7: two facts that happen
   *  to be equal are still two facts, and a rename across scripts can make
   *  them equal. */
  localName: string | null;
  latitude: number | null;
  longitude: number | null;
  startMin: number;
  endMin: number;
  endsNextDay: boolean;
  pinned: boolean;
  /** false means the plan scheduled this WITHOUT knowing when it opens. */
  hoursKnown: boolean;
  /** null is UNKNOWN. 0 is free. Never interchangeable. */
  price: number | null;
  tags: string[];
  /** The hop that got you here; null for the first stop of a day. */
  arriveBy: ExportHop | null;
}

export interface ExportDay {
  day: number; date: string; weekday: string;
  startMin: number; endMin: number;
  stops: ExportStop[];
  dayTotal: { total: number | null; unknown: number };
}

export interface ExportView {
  tripName: string;
  currency: string | null;
  days: ExportDay[];
  unplaced: { segmentId: number; name: string; reason: string }[];
  travellers: { id: number; label: string; birthDate: string }[];
  /** Markdown-only (D6): no home in ICS or GeoJSON. */
  perTraveller: { id: number; label: string; total: number | null }[];
  tripTotal: { total: number | null; unknown: number };
  calibration: Calibration | null;
}
```

- [ ] **Step 2: Implement**

Note the two coordinate conventions in one milestone: **`GEO` is
`latitude;longitude`** (RFC 5545) while **GeoJSON is `longitude, latitude`**
(RFC 7946). Getting either backwards produces a plausible location in the wrong
hemisphere, so each is asserted separately.

`DTSTART`/`DTEND` are floating local times (`20260901T090000`, no `Z`, no
`TZID`) because the trip carries no timezone and inventing one asserts a fact
the tool does not have.
