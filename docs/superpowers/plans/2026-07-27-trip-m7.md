# M7 — Query Separation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (this repo's default — M4, M5 and M6 were all implemented inline by Eric's explicit choice) or superpowers:subagent-driven-development if Eric asks for it. Steps use checkbox (`- [ ]`) syntax for tracking. **Do not dispatch subagents without asking first.**

**Goal:** A place can be looked up by one string and displayed by another, so `龙门浩老街` geocodes a segment that still reads `Longmenhao Old Street` in the plan.

**Architecture:** One nullable column, `mentions.query`, threaded through the two places a mention is created or corrected. Everything downstream reads `query ?? name` at the single point where a geocode happens. No new module, no script detection, no second lookup.

**Tech Stack:** TypeScript (strict), Bun, `@libsql/client` over SQLite, `bun:test`. Path alias `@/`.

**Design record:** `docs/superpowers/specs/2026-07-27-trip-m7-design.md`. Read it before Task 1 — decision 3 (the tool never infers) and decision 4 (the mutual-exclusion rule grows) are the two with consequences that are not obvious from the code. The reconnaissance is at `docs/superpowers/specs/2026-07-27-trip-m7-recon.md`.

## Global Constraints

- **Runtime is `bun`.** Never `npm`/`npx`/`yarn`/`pnpm`. Gates are `bun test` and `bun run typecheck`. **There is no `bun run build`.**
- **Imports use the `@/` alias.**
- **`BASE_SCHEMA` is FROZEN.** Schema changes are numbered `MIGRATIONS` entries, guarded so re-running is a no-op. Current schema is **v10**; this adds **v11**.
- **The database override is `TRIP_TEST_DB`.**
- **No shared `freshDb` helper** — each DB test file defines its own.
- **Validation at the storage layer, not only the CLI.**
- **Absence is loud.** `query` NULL means "search by the name". It must never be stored as `''`.
- **The tool never infers a local-script name and never queries twice.** Decision 3, rejected on measurement: `十八梯` returns 5 candidates where `Shibati` returns 2.
- **Purely additive.** A mentions file with no `query` must behave exactly as today, and M6's acceptance numbers (1 of 11, 4 of 11) must not move.
- **Commit per task, on `main`. NEVER push.**
- **Every task ends green.**
- Baseline: **831 tests pass, 0 fail**, schema v10, `main` at `80882f3`.

```ts
/** Set the string this mention is looked up by, leaving its name alone.

 *  is CALLED, and this corrects what it is FOUND by. Doing both through one
 *  function is exactly the collapse M7 exists to undo. */
export async function setMentionQuery(
  db: Client, mentionId: number, query: string,
): Promise<void> {
  if (query.trim() === "") {
    throw new Error("--query needs a string (omit it to search by the name)");
  }
  await db.execute({
    sql: `UPDATE mentions SET query = ? WHERE id = ?`,
    args: [query.trim(), mentionId],
  });
}
```

In `resolveCmd`, replace the action block:

```ts
  const pick = flag(argv, "--pick");
  const rename = flag(argv, "--rename");
  const query = flag(argv, "--query");
  const reject = argv.includes("--reject");

  // THE RULE, grown by M7: exactly one of --pick, --reject, or
  // (--rename and/or --query). The last two are one action because both
  // re-geocode, and they compose: --rename says what to CALL it, --query
  // says what to FIND it by, and the whole milestone is that those are two
  // facts rather than one.
  const searches = rename !== null || query !== null;
  const actions = [pick !== null, reject, searches].filter(Boolean).length;
  if (actions === 0) {
    throw new Error(
      `one of --pick=<n>, --reject, --rename="Actual Name" or --query="local name" is required`,
    );
  }
  if (actions > 1) {
    throw new Error(
      `exactly one of --pick, --reject, or --rename/--query may be given`,
    );
  }
  // Named separately from the count above so the message says WHY rather
  // than restating the rule: picking a candidate performs no lookup, so a
  // query alongside it would be silently ignored.
  if (query !== null && (pick !== null || reject)) {
    throw new Error(
      `--query re-runs the lookup, so it cannot be combined with ` +
      `${pick !== null ? "--pick" : "--reject"}, which does not look anything up`,
```
